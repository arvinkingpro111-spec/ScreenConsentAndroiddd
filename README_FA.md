# پروژهٔ «پشتیبانی با اجازه» — نسخهٔ توسعه‌ای ۱.۳

این ZIP **سورس پروژه است، نه APK آماده**. کدهای WebRTC برای تلاش جهت انتقال زندهٔ صفحه و ارسال حرکت لمس/کشیدن انگشت روی DataChannel اضافه شده‌اند. این نسخه در محیط حاضر کامپایل یا روی دو گوشی آزمایش نشده؛ بنابراین نباید آن را برنامهٔ آمادهٔ استفاده یا امن‌شده برای انتشار عمومی فرض کرد.

## قابلیت‌های پیاده‌سازی‌شده در سورس
- اتصال به سرور سیگنال‌دهی از طریق WSS و استفاده از کد موقت ۶ رقمی
- تأیید درخواست از سوی میزبان
- درخواست سیستمی Android برای اشتراک‌گذاری صفحه
- مسیر رسانهٔ WebRTC با STUN و امکان پیکربندی TURN در BuildConfig
- ارسال gestureهای لمس/کشیدن از بیننده به میزبان از طریق DataChannel
- Accessibility Service جداگانه با فعال‌سازی دستی در تنظیمات
- اعلان foreground هنگام اشتراک‌گذاری صفحه و دکمهٔ قطع اتصال

## محدودیت‌های مهم
- این نسخه **آزمایش نشده و تضمینی برای کامپایل یا اتصال موفق ندارد**. ممکن است به اصلاح APIهای WebRTC/Android، تست دستگاهی و رفع خطا نیاز داشته باشد.
- برای اتصال بین بسیاری از شبکه‌ها، STUN به‌تنهایی کافی نیست. باید یک TURN معتبر راه‌اندازی و مقادیر آن را در `app/build.gradle` تنظیم کنید.
- کنترل فعلی فقط حرکت یک اشاره/کشیدن ساده را می‌فرستد؛ کلیدهای سخت‌افزاری، متن‌نویسی، ژست‌های چندلمسی و کنترل کامل سیستم پیاده‌سازی نشده‌اند.
- دکمهٔ قطع اتصال برنامه را متوقف می‌کند؛ صاحب گوشی همچنین می‌تواند اشتراک‌گذاری را از اعلان/رابط اندروید متوقف یا مجوز Accessibility را از تنظیمات لغو کند.
- سرور نمونه احراز هویت قوی برای کاربران ندارد و برای استفادهٔ عمومی مناسب نیست. کد شش‌رقمی به‌تنهایی امنیت کافی برای محصول تجاری نیست.

## ۱) راه‌اندازی سرور سیگنال‌دهی
به یک سرور لینوکس عمومی با دامنه نیاز است. Node.js نسخهٔ ۲۰ یا جدیدتر را نصب کنید:

```bash
cd server
npm install --omit=dev
PUBLIC_ORIGIN=https://support.example.com HOST=127.0.0.1 PORT=8080 npm start
```

`support.example.com` را با دامنهٔ خود عوض کنید. برنامه فقط روی localhost پورت 8080 گوش می‌دهد؛ پورت Node را مستقیماً در اینترنت باز نکنید.

نمونهٔ Caddyfile:

```caddyfile
support.example.com {
    reverse_proxy /signal 127.0.0.1:8080
    reverse_proxy /health 127.0.0.1:8080
}
```

فقط پورت‌های 80 و 443 را در فایروال باز بگذارید. `PUBLIC_ORIGIN` باید با دامنهٔ HTTPS یکی باشد. برنامهٔ اندروید هدر Origin متناظر را می‌فرستد.

## ۲) راه‌اندازی TURN
برای عملکرد قابل‌اعتماد از شبکه‌های مختلف، به سرویس TURN نیاز دارید؛ می‌توانید از ارائه‌دهندهٔ TURN معتبر یا coturn روی سرور جدا استفاده کنید. سرور TURN معمولاً به UDP/TCP 3478 و یک بازهٔ پورت relay نیاز دارد. فایروال و گواهی TLS را طبق راهنمای ارائه‌دهنده تنظیم کنید.

در `app/build.gradle` این سه مقدار را تنظیم کنید:

```gradle
buildConfigField 'String', 'TURN_URL', '"turns:turn.example.com:5349"'
buildConfigField 'String', 'TURN_USERNAME', '"temporary-user"'
buildConfigField 'String', 'TURN_PASSWORD', '"temporary-password"'
```

این مقادیر نمونه‌اند و باید با اطلاعات واقعی سرویس شما جایگزین شوند. **رمز ثابت TURN را داخل APK عمومی قرار ندهید**؛ برای انتشار باید سرور شما اعتبارنامه‌های کوتاه‌عمر تولید کند و به کاربران مجاز بدهد. پس از تغییر، Gradle Sync را اجرا کنید.

## ۳) ساخت و آزمایش روی گوشی
1. ZIP را استخراج کنید.
2. پوشهٔ پروژه را در AndroidIDE یا Android Studio باز کنید.
3. Gradle Sync را اجرا کنید تا وابستگی‌ها از مخزن Maven دریافت شوند.
4. خطاهای احتمالی build را اصلاح کنید، سپس APK آزمایشی بسازید.
5. روی هر دو گوشی نصب کنید و آدرس `wss://support.example.com/signal` را وارد کنید.
6. میزبان کد موقت بسازد؛ بیننده کد را وارد کند؛ میزبان درخواست را تأیید کند.
7. میزبان در گفت‌وگوی برنامه، جداگانه «اشتراک‌گذاری + اجازهٔ کنترل» یا «فقط نمایش صفحه» را انتخاب کند و پنجرهٔ سیستمی Android را نیز تأیید کند.
8. برای کنترل لمس، میزبان باید خودش سرویس Accessibility برنامه را از تنظیمات اندروید فعال کند. بدون این فعال‌سازی، کنترل لمس کار نمی‌کند.

## ۴) مجوزها و شفافیت
- `INTERNET`: اتصال به سرور و WebRTC.
- `MediaProjection`: فقط با تأیید پنجرهٔ سیستمی اندروید برای اشتراک‌گذاری صفحه.
- `FOREGROUND_SERVICE_MEDIA_PROJECTION`: اعلان قابل‌مشاهده هنگام اشتراک‌گذاری.
- `AccessibilityService`: مجوز حساس کنترل لمس که فقط مالک گوشی باید دستی فعال کند.

از این برنامه فقط با رضایت روشن صاحب گوشی استفاده کنید. برای عرضهٔ عمومی، احراز هویت، اعتبارنامهٔ TURN کوتاه‌عمر، محدودسازی سوءاستفاده، بررسی امنیتی و آزمون روی نسخه‌های مختلف اندروید لازم است.

## ۵) ساخت APK آنلاین بدون نصب AndroidIDE
این پروژه یک Workflow برای GitHub Actions دارد: `.github/workflows/build-apk.yml`. برای ساخت آنلاین:
1. وارد `https://github.com` شوید و یک مخزن جدید (Repository) بسازید.
2. محتوای این پوشه را در ریشهٔ مخزن بارگذاری کنید؛ خود فایل ZIP را به‌تنهایی بارگذاری نکنید. پوشهٔ `.github/workflows` و فایل `build-apk.yml` باید در همان مسیر بمانند.
3. پس از بارگذاری، زبانهٔ **Actions** را باز کنید و Workflow با نام **Build Android APK** را انتخاب کنید.
4. گزینهٔ **Run workflow** را بزنید و منتظر پایان اجرا بمانید.
5. اگر ساخت موفق شد، در صفحهٔ اجرای Workflow بخش **Artifacts** را باز کنید و `screen-consent-debug-apk` را دانلود کنید؛ ZIP آرتیفکت را استخراج کنید تا APK داخل آن باشد.
6. اگر ساخت شکست خورد، بخش Build logs را باز کنید یا آرتیفکت `screen-consent-build-diagnostics` را بررسی کنید. کد فعلی هنوز روی دستگاه آزمایش نشده و ممکن است لازم باشد خطاهای کامپایل اصلاح شوند.

ساخت آنلاین فقط APK آزمایشی (debug) تولید می‌کند؛ این کار به‌خودی‌خود سرور سیگنال‌دهی یا TURN را راه‌اندازی نمی‌کند و برنامه بدون آدرس سرور معتبر به اتصال اینترنتی کامل نمی‌رسد. برای ساخت از GitHub Actions، Gradle روی سرور GitHub اجرا می‌شود و AndroidIDE روی گوشی لازم نیست. راهنمای رسمی Gradle/GitHub Actions: https://docs.gradle.org/current/userguide/github-actions.html
